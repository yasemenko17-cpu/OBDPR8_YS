# Стартовий проєкт OBDZ-P08

1. Відкрийте проєкт у GitHub Codespaces (Code → Codespaces → Create codespace): середовище саме підніме PostgreSQL 18 у сусідньому контейнері й задасть змінні `PGHOST`, `PGPORT`, `PGUSER`, `PGPASSWORD`. Локально: запустіть PostgreSQL 18 у Docker командою `docker run --name obdz-pg -e POSTGRES_PASSWORD=postgres -p 5432:5432 -d postgres:18`, потім `python3 -m venv .venv`, `source .venv/bin/activate` (у Windows: `.venv\Scripts\activate`), `pip install -r requirements.txt`. Якщо порт 5432 зайнятий, змініть лівий номер у `-p 55432:5432` і задайте `PGPORT=55432`, а також `PGHOST=localhost`.
2. Визначте свою задачу за номером варіанта: задача = `(номер - 1) // 3 + 1`, набір даних = `(номер - 1) % 3 + 1`. Відкрийте `variants/variant_NN.py` (NN з двома цифрами), впишіть `VARIANT = <ваш номер>` і реалізуйте функцію `scenario()` за карткою варіанта в `student.md`: вона повертає список кроків `("A", "SQL")` або `("B", "SQL")` у тому порядку, в якому їх треба виконати.
3. Схеми й початкові дані трьох наборів лежать у `data/schema_set1.sql`, `schema_set2.sql`, `schema_set3.sql`. Тести самі створюють тимчасову схему, завантажують потрібний файл, виконують ваш сценарій у двох з'єднаннях із сервером і перевіряють, що саме сталося.
4. Запускайте відкриті тести своєї задачі: `pytest -k T05` (замініть 05 на номер задачі) або `pytest -k "T05-S2"` для одного набору. Подивитися, що відбулося на кожному кроці, без тестів можна командою `python try_it.py 5`.
5. Змінюйте лише свій файл у `variants/`. Файли в `tests/` та `data/` не редагуйте.
